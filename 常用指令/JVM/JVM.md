## `jstat -gccause <pid> 5s`
- **主要功能**：
    
    - 显示年轻代（Young Generation）、老年代（Old Generation）、元空间（Metaspace）等内存区域的**使用率百分比**（如 S0=0.00, E=46.57, O=72.10）。
    - 显示年轻代 GC（YGC）和老年代 GC（FGC）的次数与耗时。
    - **最关键的是**，它会显示 **`LGCC`** 和 **`GCC`** 两列，告诉我们**上一次**和**当前** GC 事件的触发原因（例如 `Allocation Failure` 表示因内存分配失败触发，`No GC` 表示当前没有 GC）。
- **适用场景**：
    
    - **快速诊断**：一眼就能看出哪个区域内存紧张（使用率高），以及 GC 是否频繁。
    - **定位 GC 原因**：当系统出现性能波动时，可以通过 `LGCC` 列精准定位到是哪次 GC 以及为何触发，是性能调优的起点。

## `jstat -gc <pid> 5s`

- **主要功能**：
    
    - 显示各内存区域的总容量（Capacity）和已使用量（Used）的绝对值（KB），例如 `OC` (Old Generation Capacity) 和 `OU` (Old Generation Used)。
    - 同样提供 YGC、FGC 等 GC 统计信息。
- **适用场景**：
    
    - **精确计算**：当你需要知道老年代到底用了多少 GB，或者 Eden 区确切大小时，必须使用此命令。
    - **确认内存泄漏**：在怀疑有内存泄漏时，通过观察 `OU`（老年代已使用量）的**绝对值是否持续增长**，是判断泄漏的最直接证据。
## jstack 
- **功能**：打印出目标 Java 进程中所有线程的详 细信息，包括线程状态（如 RUNNABLE, BLOCKED, WAITING）和完整的 Java 方法调用栈。 
- **核心用途**： 
	- **诊断死锁 (Deadlock)**：最经典的应用。当多个线程互相等待对方释放锁时，`jstack` 的输出会明确提示“Found one or more deadlocks”。 
	- **分析高 CPU 占用**：当 Java 进程 CPU 使用率过高时，通过 `jstack` 可以快速定位到是哪个线程的代码陷入了死循环或执行了耗时的计算。 
	- **排查线程阻塞/挂起**：当系统响应变慢或某个操作长时间无反应时，可以用 `jstack` 查看线程是否因等待锁（`BLOCKED`）或等待资源（`WAITING`）而无法继续执行。 
	- **分析线程池状态**：可以查看线程池中核心线程的数量、状态以及它们当前正在执行的任务。
- 基本用法
	- `jstack [options] <pid>`
	-  **`<pid>`**：必填项，要分析的 Java 进程 ID（可通过 `jps` 命令获取）。
	- **`[options]`**：常用选项
	    - **无选项**：打印所有线程的 Java 和本地（native）方法的堆栈信息。
	    - **`-l`**：**推荐使用**。除了基本堆栈信息外，还会打印关于锁的附加信息（如 `java.util.concurrent` 的 AQS 队列中的锁），对于分析死锁和线程阻塞非常有帮助。
	    - **`-m`**：混合模式，打印 Java 和本地（C++）方法的堆栈信息，通常用于 JVM 开发者级别的深度调试。
